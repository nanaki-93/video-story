# Verification and acceptance plan

## Synthetic development fixture

Generate a small owned pack: obvious colored character pieces, unique numbered scenery strip, circular landmark, solid cabin, grayscale window mask, deterministic blinking overlay, and generated tone/silence WAVs. Mark it synthetic in metadata and watermark its previews. Fixture assets must be reproducible from a script and small enough for CI.

## Semantic unit checks

- Half-open scene intervals and exact final frame counts.
- Frame-to-sample conversion at 30/1 and one noninteger rational rate.
- Analytic travel-distance integration across acceleration, stop and restart.
- Deterministic schedule expansion and stable seed algorithm.
- Action entry/exit pose validity, prop preconditions and channel conflicts.
- Scene cut/reset rules; no unintended character duplication.
- Cache fingerprints changing on content, profile, renderer or curve edits.
- Schema migration backup and immutable snapshot behavior.
- Atomic project save, revision guard, and safe project/archive paths.

Avoid tests that only repeat implementation constants. Validate behavioral edge cases and regressions.

## Media integration checks

Render actual synthetic files with the installed FFmpeg. Probe final media, decode samples and inspect representative pixels/frames. Exterior color must appear inside the window and never outside; foreground must occlude the right pixels; alpha edges must not gain a dark matte. A one-shot landmark passes once; the numbered strip remains continuous through speed changes.

Render the same difficult sequence monolithically and as chunks. Compare decoded lossless reference frames exactly where feasible; compare lossy exports within a documented tolerance. Check global blink, rain and clip phases near every chunk boundary, rather than only duration. Verify action entry/exit and transitions that span a chunk cut.

Use sample-accurate PCM reference to test trims, overlaps, fades and silence. Final AAC tests allow codec priming/delay metadata differences but must demonstrate correct audible boundaries and no repeated gaps. Validate final end time against intended frame/sample length within one frame, with the audio rounding policy documented.

## Failure injection

Kill an owned render subprocess mid-chunk; restart worker; resume verified chunks. Change an asset in place; reject stale resume. Truncate a cached chunk; rerender it. Fill a small test output volume; show actionable error and preserve original media. Open project with missing external drive; relink by hash. Cancel a preview while final export runs; do not cancel the wrong process. Use filenames with spaces, apostrophes and Japanese characters.

Test invalid masks, unsupported fps, corrupt PNG, nonexistent codec, unapproved action pack, incompatible camera, missing transitions, malformed YAML, duplicate scene IDs, inaccessible project, port collision and protocol mismatch. Browser tests cover invalid/replayed bootstrap secrets, foreign Host/Origin, absent CSRF tokens, unauthenticated media/SSE requests, byte ranges, expired sessions, external-drive loss, path/symlink traversal, interrupted imports, stale revisions across tabs and reconnect without duplicated jobs.

## Visual and audio review

Marco reviews Tabi likeness and silhouette, alpha on light/dark backgrounds, attached face/frills, loop seams, prop continuity, landmark repetition, geographic plausibility, subtle lighting, rain placement, musical transitions and ambience balance. Watch both normal playback and key transition frames. No automated test substitutes for this approval.

## Target hardware checks

On M5 Pro/48 GB: fresh setup, dependency probing, synthetic pilot, worst-case 60-second benchmark at 1080p and 4K, available hardware encoder quality, Safari/Chromium proxy seeking/audio, memory and storage, installed local launch outside the checkout without Node/JDK, cancel/recover, backup restore and a full approved episode. Required Python/FFmpeg dependencies must be installed or reported clearly; no untested bundled-runtime claim.

CI can run Python/unit/media checks on available Linux/macOS machines, but Linux results cannot certify macOS hardware encoding, the local launcher or browser playback on the target Mac. Track each acceptance gate as passed, failed or pending with machine/tool versions. The 3 October asset audit's native decoding is evidence about the supplied files, not an FFmpeg renderer or browser acceptance result.

## Release evidence

A V1 acceptance report lists task IDs, command results, representative preview files/screenshots, final media probe, render benchmark, recovery test, verified second-scene result, package-install result, unresolved constraints and creative approvals. Acceptance requires all mandatory tasks and gates; optional ComfyUI is not a prerequisite.
